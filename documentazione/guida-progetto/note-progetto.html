01

Cos'è il progetto

È un sito web pensato per aiutare una squadra sportiva a tenere sotto controllo, in modo semplice, i certificati medici dei propri giocatori: verificare da sola le scadenze e avvisare per tempo quando un certificato sta per scadere, invece di doverlo controllare a mano uno per uno.

Accanto a questa funzione principale, il progetto comprende anche un sito pubblico con le informazioni della squadra: le categorie, le rose dei giocatori, notizie e contatti.

02

Le tecnologie usate

Tre strumenti principali, ognuno con un compito preciso:

Node.jsL'ambiente che fa funzionare il codice del server (scritto in JavaScript, lo stesso linguaggio del browser).
ExpressUna libreria che si appoggia a Node.js e rende più semplice ricevere richieste e rispondere ad esse.
SupabaseUn servizio online che offre un database vero e proprio (basato su PostgreSQL), dove sono salvati tutti i dati del progetto.

In breve: Node.js + Express fanno funzionare il server, Supabase è il "magazzino" dove i dati restano salvati.

03

Come sono organizzati i file

Il progetto è diviso in due cartelle principali: browser e server. Non stanno nel computer di chi visita il sito: stanno entrambe nel posto dove gira il server (il mio Mac, per ora).

La cartella "browser"

Contiene i tre file che il browser di chi visita il sito scarica quando apre l'indirizzo del sito:

index.htmlLa struttura della pagina: il menu, il logo, e uno spazio vuoto (chiamato "content") dove va il contenuto che cambia.
style.cssL'aspetto grafico: colori, font, disposizione degli elementi.
main.jsIl comportamento: gestisce i click e decide cosa scrivere nello spazio "content".

La cartella "server"

Contiene il codice che gira solo sul server, mai nel browser di chi visita il sito:

server.jsIl file principale: quando il browser richiede una pagina, invia il file corrispondente della cartella browser; quando la richiesta arriva su una rotta API, interroga il database e rimanda indietro i dati.
supabaseClient.jsStabilisce il collegamento con il database su Supabase, usando indirizzo e chiave segreta salvati in un file a parte (.env), così non sono scritti direttamente nel codice.
package.jsonElenca le librerie (codice scritto da altri) di cui il progetto ha bisogno per funzionare, come Express e il client di Supabase.
04

Come funziona la pagina

Il sito è fatto da un'unica pagina HTML che non si ricarica mai. Dentro index.html c'è uno spazio vuoto chiamato "content": ogni volta che si clicca su una voce di menu o su una card, main.js intercetta quel click e riscrive solo quello spazio, lasciando il resto della pagina (menu, logo) sempre uguale.

Importante: main.js non modifica mai il file index.html salvato sul disco. Cambia solo quello che si vede in quel momento sullo schermo, nella pagina già caricata.

05

Le rotte API

Una rotta API è un indirizzo del server a cui il sito può fare una richiesta per ottenere dei dati, invece di averli già scritti dentro. Il sito non parla mai direttamente con il database: parla con il server, che a sua volta lo interroga lui.

Le rotte API attive oggi sono solo tre, perché il sito serve solo a consultare informazioni:

RottaA cosa serve
GET /api/squadreRestituisce l'elenco delle squadre
GET /api/squadre/:id/giocatoriRestituisce la rosa di una squadra
GET /test-giocatoriVerifica il corretto collegamento al database
06

Il database

Sei tabelle, collegate tra loro tramite id (un numero che identifica ogni riga in modo unico).

TabellaContenuto
squadreLe categorie della società.
personaNome, cognome ed email: dati comuni a giocatori e responsabili, scritti una volta sola.
responsabiliGli allenatori, collegati alla propria persona e alla squadra che allenano.
giocatoriCollegati alla propria persona, al proprio responsabile e alla propria squadra.
certificati_mediciStorico dei certificati: ogni rinnovo è una riga nuova, non una sovrascrittura.
notifiche_inviateRegistro delle email già inviate, per evitare avvisi duplicati.

Nessun campo "stato" salvato

Lo stato del certificato (valido / in scadenza / scaduto) si calcola ogni volta confrontando la data di scadenza con quella di oggi, invece di salvarlo come valore fisso — così non rischia di restare "valido" per sempre se nessuno lo aggiorna a mano.

07

Come avviare il progetto

  1. Aprire il Terminale e spostarsi nella cartella server.
  2. La prima volta, installare le librerie necessarie con npm install (scarica il codice di Express, Supabase, ecc. dentro una cartella node_modules, leggendo l'elenco da package.json).
  3. Assicurarsi che esista un file .env, con l'indirizzo e la chiave di accesso al progetto Supabase.
  4. Avviare il server con npm start.
  5. Aprire il browser su http://localhost:3000 per vedere il sito.
08

Stato attuale

Il sito oggi è composto solo dalle pagine pubbliche (Home, Società, Storia, Squadre, Bacheca, Sponsor, Contatti): permette di consultare le informazioni della squadra, ma non ha ancora nessuna funzione legata ai certificati medici, anche se le tabelle certificati_medici e notifiche_inviate esistono già nel database, pronte per quando questa funzione verrà costruita.
